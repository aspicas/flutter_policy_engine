# Quick Start

This guide builds a small app. It loads three roles, provides the engine to the
widget tree, and shows or hides UI per role.

## 1. Define your policies

Policies use the v2 schema: a top-level `roles` object that maps each role name to
its `allowedResources`.

```dart
const policies = <String, dynamic>{
  'roles': {
    'admin': {
      'allowedResources': ['dashboard', 'posts', 'settings', 'users'],
    },
    'editor': {
      'allowedResources': ['dashboard', 'posts'],
    },
    'guest': {
      'allowedResources': ['dashboard'],
    },
  },
};
```

Resource IDs are plain strings that you choose. Matching is exact and
case-sensitive.

## 2. Create a controller and load the policies

`PolicyEngineController` owns all engine state. `PolicyEngineController.inMemory()`
stores policies in memory, which is enough for most apps that load policies at
startup.

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  final controller = PolicyEngineController.inMemory();
  final result = await controller.loadPolicies(policies);
  if (result case Err(:final error)) {
    debugPrint('Could not load policies: ${error.message}');
  }

  runApp(MyApp(controller: controller));
}
```

`loadPolicies` doesn't throw. It returns a `Result`: `Ok` on success, or `Err`
with a typed `DomainFailure`. See [Error Handling](/core-concepts/error-handling).

## 3. Provide the controller to the widget tree

Wrap your app with `PolicyEngineScope` so that descendant widgets can reach the
controller:

```dart
class MyApp extends StatelessWidget {
  const MyApp({required this.controller, super.key});

  final PolicyEngineController controller;

  @override
  Widget build(BuildContext context) {
    return PolicyEngineScope(
      controller: controller,
      child: const MaterialApp(home: HomePage(role: 'editor')),
    );
  }
}
```

## 4. Gate the UI

Use `PolicyGate` to show a widget only when access is granted. Use
`PolicyBuilder` when you need the decision itself:

```dart
class HomePage extends StatelessWidget {
  const HomePage({required this.role, super.key});

  final String role;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Signed in as $role')),
      body: ListView(
        children: [
          // Rendered only for roles that can access 'posts'.
          PolicyGate(
            roleName: role,
            resourceId: 'posts',
            child: const ListTile(title: Text('Write a post')),
          ),

          // Shows a fallback instead of hiding the entry.
          PolicyGate(
            roleName: role,
            resourceId: 'settings',
            fallback: const ListTile(
              enabled: false,
              title: Text('Settings (admins only)'),
            ),
            child: const ListTile(title: Text('Settings')),
          ),

          // Full control over the loading, granted, and denied states.
          PolicyBuilder(
            roleName: role,
            resourceId: 'users',
            builder: (context, decision) {
              if (decision == null) return const LinearProgressIndicator();
              return ListTile(
                title: const Text('User management'),
                subtitle: Text(
                  decision.isGranted
                      ? 'Granted'
                      : 'Denied: ${decision.failure?.message}',
                ),
              );
            },
          ),
        ],
      ),
    );
  }
}
```

Change `role: 'editor'` to `'admin'` or `'guest'` and hot-restart to see the gates
change.

## 5. Evaluate access in code

Outside the widget tree, for example in a navigation guard or a service, call
`evaluateAccess` directly:

```dart
final canPublish = switch (await controller.evaluateAccess('editor', 'posts')) {
  Ok(:final value) => value.isGranted,
  Err() => false, // e.g. policies not loaded yet
};
```

## What you've built

- A **policy map** in the v2 schema.
- A **`PolicyEngineController`** that loaded it.
- A **`PolicyEngineScope`** that exposes the controller to the tree.
- **`PolicyGate`** and **`PolicyBuilder`** widgets that re-evaluate whenever the
  controller changes, for example after `addRole` or `loadPolicies`.
