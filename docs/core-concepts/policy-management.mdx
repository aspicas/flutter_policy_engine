# Policies & Roles

A **policy** is the set of all roles the engine knows about. Each **role** has a
name and a set of **allowed resources**. Access is granted only when the role
exists and the resource ID is in its set. Everything else is denied.

## The policy schema (v2)

```json
{
  "roles": {
    "admin": {
      "allowedResources": ["dashboard", "settings", "users", "reports"]
    },
    "editor": {
      "allowedResources": ["dashboard", "posts", "drafts"]
    },
    "guest": {
      "allowedResources": ["dashboard"]
    }
  }
}
```

| Key | Type | Notes |
|---|---|---|
| `roles` | object | **Required.** Maps role name to role definition. |
| `roles.<name>` | object | Role names are trimmed and must not be empty. |
| `roles.<name>.allowedResources` | array of strings | Resource IDs the role may access. An empty array means no access. |

<Warning>
The v1 key `allowedContent` and the v1 flat layout (roles at the top level) are no
longer accepted. If a role entry has no `allowedResources` list, the engine skips
that role. See the [migration guide](/migration-v1-to-v2).
</Warning>

## Loading policies

### From a map

```dart
final controller = PolicyEngineController.inMemory();

final result = await controller.loadPolicies({
  'roles': {
    'admin': {'allowedResources': ['dashboard', 'settings']},
    'viewer': {'allowedResources': ['dashboard']},
  },
});
```

### From a bundled JSON asset

Pass an `IAssetLoader` when you create the controller. `FlutterAssetLoader` reads
from the app's asset bundle:

```dart
final controller = PolicyEngineController.inMemory(
  assetLoader: const FlutterAssetLoader(),
);

await controller.loadPoliciesFromAsset('assets/policies/roles.json');
```

The file must be declared under `flutter.assets` in `pubspec.yaml`. If you call
`loadPoliciesFromAsset` on a controller created without an asset loader, it
returns `Err(InvalidPolicyFailure)`.

### Loading rules

- **Loading replaces, it doesn't merge.** Every successful load overwrites the
  stored policy with the new set of roles.
- **A missing `roles` key fails the whole load** with `ParseFailure`. So does
  invalid JSON when loading from an asset.
- **Invalid role entries are skipped, not fatal.** The engine drops an entry if
  it isn't an object, has a blank name, or has no `allowedResources` list. It
  loads the valid roles and reports a warning through the injected
  [logger](/guides/logging).
- **Non-string resource IDs are ignored.** Inside `allowedResources`, only string
  values are kept.
- **Successful loads mark the controller as initialized** (`isInitialized`) and
  notify listeners, so gated widgets re-evaluate.

<Info>
Until `loadPolicies` or `loadPoliciesFromAsset` succeeds once, `evaluateAccess` on
the controller returns `Err(EngineNotInitializedFailure)`, and `PolicyGate` shows
its fallback.
</Info>

## Domain types

| Type | What it is |
|---|---|
| `Policy` | Immutable aggregate of roles, keyed by role name. Exposes `roles`, `roleFor(name)`, `isEmpty`, `merge`, `withRole`, `withoutRole`. |
| `RoleEntity` | A role: `name` (`RoleName`) plus `allowedResources` (`Set<String>`). Equality is by name only. Supports `copyWith`. |
| `RoleName` | Value object for a role identifier. Trims whitespace and throws `ArgumentError` when the result is empty. |

```dart
final editor = RoleEntity(
  name: RoleName('editor'),
  allowedResources: const {'dashboard', 'posts'},
);

editor.isResourceAllowed('posts'); // true
editor.isResourceAllowed('Posts'); // false (case-sensitive)

final seniorEditor = editor.copyWith(
  allowedResources: {...editor.allowedResources, 'published'},
);
```

## Managing roles at runtime

The controller exposes role CRUD operations. Each returns a `Result` and, on
success, notifies listeners so `PolicyGate` and `PolicyBuilder` re-evaluate
automatically.

```dart
// Add a role, or replace an existing role with the same name.
await controller.addRole(
  RoleEntity(
    name: RoleName('reviewer'),
    allowedResources: const {'dashboard', 'drafts'},
  ),
);

// Replace the role called 'reviewer' with a new definition.
await controller.updateRole(
  'reviewer',
  RoleEntity(
    name: RoleName('reviewer'),
    allowedResources: const {'dashboard', 'drafts', 'posts'},
  ),
);

// Remove a role. Removing a role that doesn't exist is a no-op.
await controller.removeRole('reviewer');

// Read all roles.
final roles = switch (await controller.listRoles()) {
  Ok(:final value) => value, // unmodifiable List<RoleEntity>
  Err() => const <RoleEntity>[],
};
```

| Method | Behavior |
|---|---|
| `addRole(role)` | Adds `role`, overwriting any role with the same name. |
| `updateRole(name, newRole)` | Removes the role called `name`, then adds `newRole`. If `newRole` has a different name, this renames the role. If `name` doesn't exist, `newRole` is simply added. |
| `removeRole(name)` | Removes the role. No-op if it doesn't exist. Returns `Err(InvalidPolicyFailure)` for a blank name. |
| `listRoles()` | Returns all current roles as an unmodifiable list. |

<Warning>
Role CRUD doesn't mark the controller as initialized. If you build all roles with
`addRole` instead of loading a policy, call `loadPolicies({'roles': {}})` first.
That initializes the controller with an empty policy, and later additions then
become evaluable.
</Warning>
